# 創作定位與決策範圍

更新：2026-10-19 JST　｜　性質：**已確認方向 + 參考提案**，不是完整定案的 GDD。

## 遊戲希望帶給玩家的感受

先因**謎團、角色、危機與冒險**喜歡上遊戲，再透過親自調查，逐漸理解人們如何在當時有限的知識下觀察、懷疑、辨識反例、修正判斷與承擔後果。

系列長期涵蓋科學、醫學、航海、金融、工程及資訊史；各篇獨立好玩，由同一位時空旅人／神祕 Hub 串成跨年代長線，但**這次 MVP 不製作 Hub**。不把系列鎖死為教科書式的「偉人科學史」。

## 目前確認（Owner）

1. 第一款優先測試 1854 倫敦霍亂懸疑《沒有名字的病》（工作標題），第一案〈沒有染病的人〉。
2. 玩法路線 **A → C**：先完成有趣的 **A 定點調查 + 玩家主動組合證據推理**；通過試玩後才升級 **C 的角色動畫、鏡頭與轉場**。不先做自由走動的倫敦地圖。
3. 第一案以**異常與矛盾的病例**勾起好奇；科學不是單選題，玩家不被動等待「播放正解」。
4. 真實人物／歷史不得為劇情需要被抹黑，亦不得用後世確定答案讓主角替當代研究者完成他們的發現。
5. Opus 帶隊作為 Game Director，工程可委派 Sol/Codex；四天密集衝刺以真正可玩的原型為目標。使用 pnpm，不使用 npm。
6. 第一版桌面瀏覽器／繁體中文優先，核心玩法交付勝過美術規模。

## 候選提案（Opus 可自行修改）

- 玩家：虛構的地方紀錄助理，可接觸病例、訪談居民與整理地圖。
- 4–6 分鐘 Day 1 垂直切片，一間紀錄室、三份可重看的線索，玩家自己建立第一條推論；四天目標為 15–20 分鐘獨立故事。
- 後續場景候選：啤酒廠、濟貧院／附近街道與 Broad Street 水泵。
- 目前三組假說：污濁空氣解釋、近距離接觸解釋、共同飲水暴露解釋；注意第二項與第三項在疾病傳播機制上**不必互斥**，不能設計成三個完全排他的科學真理。
- 技術候選 Phaser/TypeScript 或更輕的 TypeScript/DOM；由 Opus 用真實瀏覽器 PoC 決定，不預設引擎是既成決議。

## 系列的深層連結

- 航海定位與 1919 日食：測量誤差與證據可靠性。
- 霍亂調查與登月警報：在資訊不完整而時間有限時，何時應採取行動？
- 航海、金融與工業：路線、消息延遲、風險、投資與技術革新的跨領域長線。

不要在第一作塞入全部主線；留待玩家玩過多篇後自然領悟。

## 文字與歷史準則

「沒有名字的病」**是文學化名稱**：1854 年人們已知道霍亂（cholera）這個病名；不確定的是傳播原因與介入方法。

故事／證據欄位至少標註：
- `HISTORICAL_RECORD`：原始來源明載的事實（需附具體出處）。
- `RECONSTRUCTION`：從史實合理推得，但具體時間、口吻、道具為藝術重建。
- `FICTION`：虛構人物、對話、旁支情節。
- `DISPUTED`：有歷史爭論、史料不足或不同來源說法，不能在劇中斷言。
