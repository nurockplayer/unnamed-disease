# 第一案〈沒有染病的人〉：原型企劃／可驗收切片

**狀態：供 Opus 執行的最小目標**。此文件是製作簡報，不是已完成清單。採用 [專案定位](PROJECT_CONTEXT.md)、[證據表](EVIDENCE_REGISTER.md) 與 [史實](HISTORY_1854.md) 作為背景。

## 核心玩家承諾

「死者接連出現，附近一家啤酒廠卻幾乎無重症。為什麼？」  
玩家不是從問答題選出 `霍亂是水傳播`，而是從死亡登記、生活習慣與互相矛盾的證詞中，主動拼出一段**暫時成立、仍可質疑**的推論。

**作品標題《沒有名字的病》是隱喻**：當時已有霍亂病名，沒有定論的是疾病如何傳播。

## Day 1：4–6 分鐘的遊戲，不是 UI Mockup

### 限定範圍

- 一個定點場景：**紀錄室**（視角／視覺由 Opus 決定）。
- 三份可獲得、可重看證據：E01 群聚／死亡登記、E02 啤酒廠工人病例、E03 啤酒廠取水來源。
- 至少一個 NPC（可虛構）的短對話／回應。
- 一個可**由玩家選擇兩項證據**建立的推論；錯誤或不足的組合有意義地回饋，可繼續調查。
- 一個可見的小結局／下一階段懸念；能重玩。
- 桌面瀏覽器、繁體中文；音效和背景圖可用暫定素材，不可擋住玩法驗收。

### Day 1 畫面交互節奏建議

1. **0:00–0:45｜鉤子**：「街角又有人死了。可那家啤酒廠，照常開門。」（**虛構台詞**）
2. **0:45–2:30｜探索**：點擊桌上登記冊、調查紙張、取水筆記；每件都有可重讀的新資訊。
3. **2:30–4:30｜推理**：玩家選 E02 + E03，建立「距離不是唯一差異，取水來源值得查」。
4. **4:30–6:00｜反應**：角色提出下一個問題「那隔壁的濟貧院呢？」；第一個案件段落結束。

**第一個 aha moment** 是「玩家靠自己排除了**單靠街區位置**就解釋疾病風險的想法」，不是公布現代標準答案。

### 必過驗收（自動測試不能取代實際遊玩）

- [ ] 第一次啟動可進入遊戲；不需看 README 或 devtools。
- [ ] 3 個互動點各自提供不同、有用的情報；可重看。
- [ ] **沒組合證據前不會自動出結論**。
- [ ] 玩家可以主動選 2 個證據提出推論；充分／不足時有不同反饋。
- [ ] **錯誤操作不能 softlock**；能重試、重開、走到結尾。
- [ ] 真實瀏覽器可從「新遊戲」走到小結尾（不靠工程快捷鍵）。
- [ ] 至少一個自動化回歸情境＋真實瀏覽器測試紀錄。
- [ ] 專案內留下已知問題、史實參考與下一步的 GitHub Handoff。

**不算完成**：只有圖、動畫、字卡、3D 漫遊、純對話、固定順序看完素材後遊戲自動破案。

## Day 2：擴充為一個完整 15–20 分鐘案件

- 增加第二、三個定點場景（暫定啤酒廠、濟貧院或 Broad Street 水泵）。
- 加入 E04/E05 的近距離反例及 E06（如採用需在 **9/9 或之後** 才能取得正確情報）、E07 小地圖。
- 結尾是玩家提供附理由的判斷、NPC 回應、少量結局差異。
- 真實史實重大結果保持不變，不承諾主角能阻止已發生的死亡。

## Day 3：趣味與懸疑節奏

- 讓**不知道答案的試玩者**直接打開遊戲，不提供口頭教學。
- 記錄：何時知道目標？有沒有自行發現反例？何時無聊／卡關？能否說出自己的推理？
- 修提示、點擊範圍、文字密度、反例提示、聲音與 UI 反饋。
- 只有核心推理先成立，才小幅增加 **C** 的鏡頭移動、分層場景、動畫與轉場。

## Day 4：可分享版本與交接

- 真實桌面瀏覽器從頭走通、重開測試、基本互動／錯誤回歸。
- 在 Repo 留下能啟動與試玩的明確方法；有部署網址就記錄網址，無則記錄本機啟動方法。
- 統一史實／重建／虛構標記，寫出研究來源與未完成的史實缺口。
- 第一款確實可玩且品質過關，才可研究第二款《雲層之後》短切片。**第二款不是 Day 4 必達項目。**
