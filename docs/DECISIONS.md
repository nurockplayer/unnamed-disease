## D007 — 第一版採用 Web（Vite + TypeScript，無遊戲框架）

- 日期 / 決策者：2026-10-19 / Opus 5.5（Game Director，依 D006 授權）
- 狀態：accepted（可逆；C 演出階段若 Web 明顯不足再重評）
- 決定：Case 01 以**原生 DOM + SVG + CSS** 的 Web 遊戲實作；Vite 建置、TypeScript、pnpm；Vitest 測推理判定邏輯，Playwright 在真實 Chromium 走完整流程；可用 GitHub Pages 靜態分享。
- 理由：
  - 玩法 A 是「閱讀文件＋組合證據＋對話」，核心是繁中排版、可讀性與 UI 回饋；HTML/CSS 對 CJK 字體、文字密度、無障礙與 RWD 的成本最低。
  - 本環境可直接在瀏覽器實玩、截圖並以 Playwright 自動回歸；Godot 4.7 雖已安裝，但其視窗內遊玩難以自動化驗證，Web 匯出還需處理 CJK 字型與 SharedArrayBuffer/執行緒標頭。
  - 分享成本：一個網址即可試玩，對盲測最友善。
  - A→C 彈性：C 的鏡頭推移、分層場景、轉場可用 CSS/SVG 動畫或之後局部引入 Canvas/WebGL；推理資料層（content/logic）與呈現層分離，必要時可移植。
- 考慮的替代方案：
  - Godot 4.7（原生或 Web 匯出）：C 演出更強，但四天內文字 UI、字型、自動化 E2E 成本較高 → 暫不採用。
  - Phaser／其他 Canvas 引擎：對以文件為主的 UI 幫助不大，反而要自行處理文字排版 → 不採用。
  - React/Preact：UI 規模小，先不引入框架；狀態集中於純函式 reducer，日後要換也容易。
- 對可玩版本／史實的影響：證據卡資料含 `provenance`（史實／重建／虛構）與 S01 頁碼，遊戲內可展開「史料註記」。
- 相關：Issue #1。

## D008 — 推理板改為「找出差別」，不再挑選寫好的結論句

- 日期 / 決策者：2026-10-19 / Opus 5.5（依第一輪盲測）
- 狀態：accepted
- 問題：v0.1 推理板讓玩家從 5 句完整結論中挑一句。盲測回報：正確選項是唯一「長而保留」的句子、幾乎複述筆記，玩家「停止推理、開始比對句子」。另有兩個不公平回饋：登記冊（明寫無啤酒廠工人死亡）＋筆記被判「沒證明他們沒事」；沒選水的證據時，黑爾卻說「他們用別的水」。
- 決定：題幹固定為「就在疫區正中間，有一群人幾乎沒事。他們和死去的街坊，差別在於——」，玩家選兩份證據＋一個差別：吸的空氣／住和做工的地方／從事的行業／喝麥芽酒／取水的來源／運氣與體質。
  - 空氣、地點：只要板上有「這群人沒事」的證據，就被**排除**（「這正是他們和街坊一樣的地方」）——即 CASE_01 要的 aha：位置不足以解釋。
  - 行業：登記冊上有 Broad Street 雷管工廠工人死亡（史實背景 S01 p.43），被排除。
  - 麥芽酒：老闆「認為」工人不喝水是證言，判為說過頭。
  - 取水來源：需要筆記（E03）＋「他們沒事」的證據（E02 回信或 E01 登記冊）才成立；E01+E02 是「有效的觀察但還不夠」。
- 其他：證據心得不再預先寫出對比；黑爾在連續失敗 3 次後給方向提示；桌面「重新開始」改為兩段式確認；對話框焦點管理與螢幕報讀（Codex 審查）。
- 影響：正解仍唯一（水＋E03＋E01/E02），但每個錯誤選項都由證據排除，結尾總結列出玩家排除過的差別。

## D010 — 第二段先讀供水證詞，再用反例檢查分法

- 日期 / 決策者：2026-10-25 / Sol（依本次第二段難度調整委託；可逆的 MVP 實作決定）
- 狀態：implemented；獨立設計／史料 sanity check 未取得回覆，見下方工具失敗紀錄。不是人類盲測通過。
- 問題：熟悉 Snow 故事的人可先猜「水」，其他欄位像陪襯；原本回饋又一次標出所有錯格，先全填「是」再反轉紅格即可不用閱讀。
- 決定與理由：
  - 保留 **4×4 可填格子**與既有欄位意義。額外列出唯讀的「有霍亂死亡通報」條件（由結果摘錄，不多收一組存檔格子）。啤酒廠＝否、濟貧院／雷管工廠／咖啡館＝是；它吻合三列，直到玩家注意到 **535 名原有住民中 5 死的濟貧院**也有死亡通報，卻是相對輕的例外。它是容易誤用的觀察分法，**不是一個致病原因**。
  - E05 不直接在本文及心得說出「不用 Broad Street 水」，而是寫**院內井泵＋Grand Junction 供水，不差人到街口排隊**。玩家須分清「有泵」和「來自哪一口井」。E09 則須沿**廠內水桶 → 街泵來源**往回讀，不能從喝水處或死在家裡推斷水源。
  - **16 格全對＋選對水源欄才成立**。沿用 `insufficient` 回覆而非 `partial`：選對方向還不能代替證據，而且原提示計數不把 `partial` 算成失敗；這樣連錯三次仍有出路。未填完不能提出，填錯可無限修改。
  - 錯誤回饋只指向第一個需重讀的**整列**，同列不同錯法收到相同文字；不再公布逐格紅色答案或錯誤格數。列內可直接重讀已收集的來源，格子與選項保留，關閉文件後回到街上再開推理板。
  - 三次失敗後，黑爾明說院內井泵／街泵水桶的差別，以及濟貧院「五百多人只死了幾個」對「有死亡＝一樣嚴重」的反例（Snow 事後的 535／5 只記在 provenance）。提示帶回證詞，沒有懲罰或次數限制。
- 史實與表達邊界：
  - S01 pp.41–42：咖啡館午餐供街泵水、已知九名顧客死亡；常客總數不詳，**不能排名死亡率**。
  - S01 p.42：濟貧院 535／5、不含發病後才入院的人；院內 pump-well、Grand Junction 供水、不派人到 Broad Street 取水。啤酒廠沒有工人死亡登記、無重症但兩人輕微不適；這不表示全員完全健康或酒能防病。
  - S01 p.43：雷管工廠約 200 人，兩桶街泵水供想喝的人飲用；最終 18 人死於各自家中。9/6 台詞只說「好幾個」，不把最終統計冒充已證實的當日人數。
  - 本文人物／對話仍為 FICTION；E05 的改寫與提前訪問、E09 的主角筆記明標 RECONSTRUCTION。只比較四份記錄，不聲稱每個人均有相同暴露、四列證明普遍因果，或主角替 Snow 發現水源說。
- 考慮的替代方案：不加新地點以免增加史料與閱讀負擔；不把原 `crowd` 格子改成死亡通報（避免舊存檔格子改義）；不逐格扣分或加限次。第三段較低優先，本輪略過。
- 相容：v3 儲存鍵、State/cells 形狀、原四欄正解與已解進度不變。`reviewRow` 只是可選回饋資料；保留舊 `wrongCells` 型別以容納先前回覆。首版沒有修改 `state.ts`、`main.ts` 或結案畫面；2026-10-25 修訂另動了 `state.ts`（`tableFilled`）與結案文字，見下。
- 設計 sanity check：實作前兩次使用指定 oracle-ego，均未送達 ChatGPT，**沒有審查意見可以引用**。初次 exit 1，run `20261025-133307-95458-part2-design`：render 嘗試 chmod sandbox 外的 `~/.oracle/sessions`；以 CLI 支援的 `ORACLE_HOME_DIR` 移入允許目錄後，第二次 exit 5，run `20261025-133527-98132-part2-design-sandbox`：Ego Lite 啟動被 sandbox 的 macOS 服務連線拒絕。沒有改用其他模型／傳輸。史料由實作者直接核對 S01 原文；獨立檢查仍未完成。最終 diff review 結果另在 PR 記錄。
- 驗證：Vitest 窮舉 65,536 種是／否表格 × 五條件＝327,680 次提交，唯一解；另測每一格空白 × 五條件、同列錯法不洩漏格子、三次失敗後可重讀修正。E2E 覆蓋誘餌排除、錯水源、提示、重讀、續存、鍵盤修正及固定舊版存檔。
- 本機結果：`pnpm test` 22／22；build 通過。E2E 的 18 個測試均在 bundled Chromium 啟動時被 sandbox 拒絕 MachPort 權限（SIGTRAP），沒有執行遊戲斷言，不能算通過；未原樣重跑。推送後既有 CI 的結果與最終 review receipt 另見 PR。
- 2026-10-25 修訂（PR #6 oracle 審查後）：
  - **結果欄先藏起來**：16 格全部填完（不要求填對）前，「結果」與「有霍亂死亡通報？」兩欄顯示「？（填完表再對照）」，欄位選擇也一起上鎖（新增 state 層 `tableFilled`）。填完才列出結果、才准選欄；填錯仍只回「整列」提示。這擋住「先看結果再反推供水欄」的捷徑，也讓玩家先讀證詞再對照。
  - **E05 補回 p.42 的關鍵事實**：院內有自己的井泵、Grand Junction 供水，且住民從未派人到 Broad Street 街泵打水（取代上面「不直接說出不用 Broad Street 水」一項）。先前的改寫反而讓 pump=false 無法從證詞唯一推得。
  - **9/6 不說最終統計**：門房改說「五百多人，只死了幾個」，工頭改說「好幾個工人」。精確的 535／5、18／200 只留在 provenance 的 source note，並註明是 Snow 事後統計；表格結果欄、謎題回饋、三次失敗提示與結案文字同步改成模糊說法。
  - **咖啡館的 crowd=false**：E10 加一句老闆娘的話（常客是附近各自做工、來吃午飯的人，店裡只有她和一兩個幫手），並在 provenance 標 FICTION。結果欄改「已知九位常客死亡（常客總人數不詳）」；`solved` 回饋與結案頁只說死亡通報「比較多／比較少」，不評咖啡館比較危險。
  - **已知殘留：逐列暴力試**。`reviewRow` 固定回第一個錯列，玩家可把 16 格任意填滿、選 pump，再對該列枚舉最多 16 種是／否組合；提示移到下一列，就知道前一列四格全對。逐列最多約 64 次提交可通關。**接受理由**：目標受眾是一般玩家、偏易；正常遊玩會先讀證詞再填格，不需要也不會有耐心做這種搜尋。不限制提交次數是刻意的（錯誤不是懲罰）；改成隨機或延遲回饋會增加理解成本、傷害正常玩家。此風險記錄於此，不再修。

## D011 — 主角改為替 Snow 核對資料的登記處助手

- 日期 / 決策者：2026-10-25 / ud-director（Game Director，依史實稽核 F6）
- 狀態：accepted
- 問題：原本的對話讓 9/5–9/6 的主角先得出「差別在取水來源」，再讓黑爾先生複述；讀起來像主角比 Snow 先發現水源假說，與史實（Snow 自 9 月 3 日起已懷疑街泵；他之後才取得已登記的死者名單，日期原書未載）及 `HISTORY_1854` 的提醒衝突。
- 決定：
  - 主角定位為本分區登記處的臨時抄寫助手；工作是核對與蒐集證據，不是提出假說。過場 `to2` 由黑爾先生說明：斯諾醫生這幾天一直在懷疑那口泵（不說出確切日期：9 月 3 日是 Snow 1855 事後的記載），上頭要登記處把紀錄整理出來給他核對。玩家仍從證據自行推理，但水源的方向是 Snow 先提出的。
  - E04 的「該死上一百多人」改由黑爾先生自己照四周的情況推算（不宣稱 Snow 在 9 月 6 日之前已算出）；provenance 另註：Snow 在 1855 年的書裡做過同樣的估算（p.42），但何時算出史料未載。
